# Text Extractor

macOS and Windows. On Mac, Text Extractor requires macOS 14 or later. Open **Settings → Advanced** and enable **Text Extractor**. **Win + Shift + T** opens the editor flow: after release, the selected crop flies from its original rectangle into the screen's center, then settles above the editor as the text appears. Basic OCR runs during the flight. **Ctrl + Win + Shift + T** selects an area over the live desktop, reads it locally, copies the text, and closes without showing a screenshot, editor, or buttons. Both shortcuts can be changed independently in Settings. Duplicate assignments and combinations already registered by another application are rejected while keeping the previous shortcuts. Legacy preferences acquire the Quick Copy default automatically; the former Ctrl + Shift + E and Ctrl + Win + Shift + T editor defaults migrate once, while explicit custom assignments are preserved on subsequent launches.

On Windows, when assigned to either action, the two default combinations are intercepted by a hidden Pulse helper process while enabled, consuming the T press, repeat, and release before Windows' Snipping Tool sees the chord. Other keys and modifier releases pass through. Modifier state is tracked directly, with no typed text recorded. A bounded non-blocking queue sends actions off the hook thread. The helper has no WebView2 windows, so focusing Settings cannot bypass its hook. Private inherited pipes carry shortcut configuration and actions; closing Pulse closes the input pipe and terminates the helper. The same executable starts the helper before initializing Tauri, so there is no second tray icon or additional download. Disabling the feature restores Windows' normal shortcut handling. Other custom combinations use Windows global shortcut registration. Shortcut recording reports either intercepted chord or an existing registered custom shortcut to the active recorder without starting a capture.

Basic is the initial default for both shortcuts. Without an available Advanced provider, both shortcuts use Basic, and the editor shows the screenshot, editable text, **Translate**, and **Copy**. A signed-in local Codex with Luna access is the preferred Advanced provider; a shared OpenAI API key is an alternative. Either adds **Basic / Advanced** above the screenshot; Settings exposes a default mode slider for each shortcut. Advanced Quick Copy sends only the selected crop to the selected provider and copies its result without an editor. The default modes persist independently. An Advanced editor default starts centered with the zoomed screenshot and shimmer, then reveals its result after the current shimmer pass finishes.

Switching to Advanced fades away the editor, centers the screenshot and slightly enlarges it, then runs a broad full-height shimmer from left to right. When the model's result arrives, the current 2.4-second pass finishes at the right edge before the screenshot shrinks and moves upward and the editor and buttons fade in below it. Switching modes retains each mode's edited draft, cancels the previous request, and reuses completed results without another paid call. Reduced motion skips the flight, zoom, and shimmer wait. Errors leave the mode selector usable and preserve existing edits.

Edit the returned text and choose **Copy** to copy and close. **Translate** opens a language picker and replaces the current mode's editor content with a translation of its current text. Press **Escape** or click outside the result to dismiss; invoke the shortcut again to take a fresh capture. A drag that starts inside the editor does not dismiss the overlay when released outside.

Screenshot and editor use squircle corners where the system webview supports them, with rounded corners as a fallback. The translation symbol comes from `src/translation-icons/translate-icon.svg` on the Live Translate branch, with the background circle removed. Both centered pills use the same foreground and background colors, with Translate on the left and Copy on the right. Accessible status announcements are offscreen; there are no visible hints, headings, or close/reselect/done controls.

The monochrome overlay follows Pulse's Appearance selection, including the resolved Auto schedule on Windows. On Mac it follows the system appearance. The native window is created with Pulse's current visual theme and updates through the same controller as the tray, including transition rollbacks. The webview exposes that theme through `prefers-color-scheme`. The blurred backdrop is grayscale; the selected screenshot retains its original colors.

Settings has **General**, **Advanced**, and **Appearance** pages with a sliding tab indicator and keyboard navigation. General contains startup behavior; Appearance contains Auto scheduling and tray/menu-bar icon style. The Advanced page contains Text Extractor and Advanced access on both platforms. When Codex is installed, a **Codex / API key** selector chooses the provider; otherwise only the existing API-key form appears. Mac adds a Screen Recording permission action. Page changes preserve saved state and close open dropdowns. The selected settings pill is black in light mode and white in dark mode. Identical, counter-moving labels are clipped inside the sliding pill so the selected color follows its edge without changing the font; reduced motion and forced colors have accessible fallbacks.

Settings is a wider floating squircle panel with an internal title, a draggable header, and a centered **Done** button. Done and Escape dismiss it; there is no native title bar or close button. Shortcuts expand and collapse smoothly with the Text Extractor toggle. With an available Advanced provider, the compact mode sliders sit immediately to the left of their shortcut buttons. The panel follows Pulse’s current appearance and keeps the same size across pages, with scrolling on short screens or when errors need extra space.

## macOS integration

Mac defaults are **Option + Shift + T** for the editor and **Control + Option + Shift + T** for Quick Copy. All combinations use the system global-shortcut registrar; Windows-specific keyboard interception remains isolated under `src-tauri/src/text_extractor/windows/`.

`session.rs` owns the shared windows, cancellation, crop binding, clipboard, notices, and animation IPC. Native adapters provide capture, positioning, shortcuts, and Basic OCR. Mac uses a small Objective-C bridge to AppKit, ScreenCaptureKit, and Vision. It tracks each display's ID, global point coordinates, and backing-pixel dimensions separately, positions overlays on that display across Spaces/fullscreen apps, excludes the selector and notice from capture, and exports SDR sRGB pixels. Permission is requested only through the Settings button; startup and prewarming never request screen access or capture pixels. Revoking permission or disconnecting/changing a display fails the capture rather than using stale geometry.

Basic uses `VNRecognizeTextRequest` revision 3 in accurate mode with automatic language detection, prioritizing system languages plus English, Ukrainian, and Russian when supported. Language correction is disabled to preserve identifiers and literal text. The output keeps word spacing, groups fragments by row, and retains paragraph gaps. It needs no API key, ONNX Runtime, or model download. OCR runs off the event thread; cancelling discards any late result.

Advanced extraction and explicit translation fallback use the selected Codex or API-key provider on both platforms. Basic OCR and Google translation remain available without either provider.

The build script compiles the Objective-C capture/OCR bridge and links AppKit, Vision, and CoreGraphics. ScreenCaptureKit is weak-linked, with capture guarded to macOS 14 or later so older supported Macs can still launch the menu-bar app. No additional model framework or cloud entitlement is required.

This reconfiguration was compiled without running capture, OCR, model requests, clipboard actions, UI previews, or the acceptance pipeline. Manual Mac checks remain: permission grant/revocation, both shortcuts, recording/custom bindings, Retina/mixed-DPI displays, negative origins, Spaces/fullscreen, tiny/mixed-language crops, animation timing, appearance, notices, API-key controls, and cancellation. The historical Windows results below do not validate this new Mac integration.

## Codex subscription provider

Pulse discovers executable Codex installations in standard desktop-app, Homebrew, local-bin, PATH, and Windows npm locations. Windows Microsoft Store packages are resolved through the current user's package registry using a bounded, hidden PowerShell query. Discovery runs in the background at launch and refreshes when Settings opens; Retry rechecks sign-in and model availability. No Codex installation means no Codex option. Installed but signed-out, outdated, or Luna-incompatible installations show a short status and Retry. Sign in or update in Codex itself; Pulse does not install Codex or handle its login credentials.

Some Windows Store packages prevent external applications from launching their bundled executable. Pulse tries a separately installed Codex CLI next; if none works, Settings explains that this desktop installation needs the CLI. Pulse does not change package permissions, copy protected executables, or modify the user's Codex configuration.

The provider defaults to Codex, including for existing preferences without a provider field. An explicit API-key choice persists. If Codex is absent, Pulse offers the API-key flow automatically. Discovery does not generate text or spend model tokens: it initializes `codex app-server` over private stdio, calls `account/read` and `model/list`, then closes it. A ChatGPT sign-in and an advertised image-capable `gpt-5.6-luna` are required. Installed-but-unavailable Codex never silently switches a request to API billing. Basic OCR stays local.

Model calls follow Codex's [temporary structured request pattern](https://github.com/openai/codex/blob/main/codex-rs/tui/src/temporary_structured_request.rs) through the [app-server protocol](https://learn.chatgpt.com/docs/app-server). This is an isolated use of the Codex runtime, not a direct subscription REST endpoint or an interactive coding agent. Each request starts an ephemeral thread with no workspace roots or environments, tools, shell, browsing, skills, plugins, hooks, memories, and MCP servers disabled, and explicit extraction/translation instructions. Pulse refuses server-initiated actions and model reroutes. A strict JSON result schema returns only the text field to the editor. The app-owned scratch directory contains only a static instructions file; image input travels as an in-memory data URL. No auth files or tokens are read by Pulse, returned to the webview, or copied into its key store.

Codex owns subscription authentication, upstream networking, and plan limits. Pulse uses the lowest reasoning effort advertised for Luna: `none`, then `minimal`, then `low`. API-key requests retain `none`. Closing, switching modes, or starting another capture cancels the dedicated process; requests have bounded startup and completion timeouts, bounded frames/text, and ephemeral-thread cleanup. The app-server experimental API can change between Codex releases; unsupported versions fail with a status and the API-key alternative remains available.

The ignored Rust test `installed_codex_extracts_and_translates_fixture` is an explicit subscription-consuming check, separate from normal tests. Set `PULSE_CODEX_TEST_IMAGE` to a synthetic PNG containing only `Pulse OCR 42`, then run `cargo test installed_codex_extracts_and_translates_fixture -- --ignored --nocapture` in `src-tauri` on an authorized test machine. It exercises automatic discovery, image extraction, Ukrainian translation, and cancellation without capturing the screen or touching the clipboard. Do not run it on a user's machine without permission.

Windows verification on 2026-09-15 used an isolated source directory and the installed Codex CLI 0.153.4 with a ChatGPT sign-in. Formatting, Clippy with warnings denied, and 51 unit tests passed. The separate live Rust bridge check extracted `Pulse OCR 42` exactly and returned Ukrainian text for translation. ## Capture and request lifecycle

Pulse prepares a hidden transparent webview when the feature is enabled and after a capture closes. The shortcut path only reads monitor geometry, positions that preloaded window, and shows the live selector; it does not capture/encode a screenshot, transfer pixels, or read credentials. Native window entrance transitions are disabled. The selection surface intercepts the mouse over the live desktop, including monitors left of or above the primary display.

Pixels are captured only on release. Windows Quick Copy captures only the crop; Mac captures the selected display and crops its backing pixels. Quick Copy hides the selector, and runs its configured recognizer without returning images or text to the webview. Empty recognition leaves the clipboard intact and shows the small “No text found” notice; failures preserve the clipboard and report the error in Settings. A new shortcut cancels pending Quick Copy work so a slow Advanced request cannot block a fresh selection or overwrite its clipboard result. The editor captures the selected monitor once and retains a top-down BGRA buffer. Only the bound crop is converted and PNG-encoded before its flight starts. A separate cancellable command prepares a small backdrop while the crop is already moving; neither backdrop encoding nor decoding gates the animation. Only after selection is the frozen background blurred. Other monitors are untouched. The selector is excluded from capture with `WDA_EXCLUDEFROMCAPTURE` (Windows 10 version 2004+).

Closing the last selector does not quit Pulse; explicit Quit and updater restart still work. The replacement selector is prepared in the background. The keyboard hook only updates shortcut state and sends a non-blocking action; Windows-menu input masking runs on the action thread. Remapped/injected shortcut keys are supported, and only the tagged unused mask key is ignored. When a capture closes, the next hook event resynchronizes modifier/T state with Windows, recovering releases consumed while the selector was focused and preserving repeat suppression if the original chord is still held.

Every active and preloaded window has a unique label. Ready/start handshakes avoid cold-webview startup work, and matching-label cleanup prevents a delayed watchdog or cancelled Quick Copy from closing a newer session. Display changes invalidate the selected monitor geometry before capture. On Windows, Basic uses PP-OCRv5 Mobile detection and Cyrillic recognition through CPU ONNX Runtime. It handles Latin and Cyrillic text in one pass, including English, Ukrainian, and Russian, without Windows language packs. The runtime is statically linked into Windows builds; there is no Python, GPU driver, or separate runtime installation. Models download once when Text Extractor is enabled and preload in the background. Valid cached models load without a network request. Settings shows setup progress and Retry if setup fails; Basic reports that setup is needed until the sessions are ready and never falls back to a paid request. Advanced uses OpenAI Luna on both platforms.

Model URLs and SHA-256 digests are pinned to the RapidOCR v3.9.2 registry in `src-tauri/src/text_extractor/windows/ocr_models.rs`. Requests identify Pulse with a User-Agent because ModelScope’s CDN rejects an absent header with HTTP 403. If ModelScope fails, each file falls back to the DjB314/RapidOCR Hugging Face mirror pinned to commit `04e88d0483f0bfcdd0f29429594244c10bfc2867`; both sources must match the same upstream SHA-256 digest. HTTP/network failures are logged without signed CDN URLs, and Settings identifies failed sources if both hosts fail. Disk errors stop immediately instead of retrying another host. Both downloads require HTTPS, have bounded size/timeouts, and are verified before partial files are renamed into the versioned cache in `%LOCALAPPDATA%/app.pulse.desktop/ocr/ppocr-v5-cyrillic-rapidocr-3.9.2`. Existing files are verified at startup; corrupt/incomplete downloads can be retried. Disabling cancels setup; re-enabling uses existing verified downloads. Prepared CPU sessions are retained until exit, with idle thread spinning disabled. Licenses and upstream attribution are bundled in `src/ocr-notices.txt`.

The recognizer reads dictionary line terminators without creating an extra empty character and verifies the dictionary length against the model output. This keeps the final space class at its correct index, instead of dropping all spaces within a detected line. The downloaded weights remain unchanged. Small selections keep background-matched padding and bounded enlargement. Detection is limited to a 1536-pixel long edge, recognized fragments are grouped into rows and read left-to-right, and empty/low-confidence output leaves the clipboard untouched. This initial integration targets upright screen text; quality, speed, and very small/mixed-language crops still need the user’s Windows acceptance run. No model inference, benchmarks, or tests were run for this replacement, at the user’s request.

Only Advanced sends the crop to OpenAI: through the selected local Codex runtime, or to `https://api.openai.com/v1/responses` with the API key, `gpt-5.6-luna`, `reasoning.effort: none`, and `store: false`. The prompt requests only the intended main text, in its original language. Screenshot instructions are treated as source text. Pulse keeps images in memory and discards them when the capture closes; it writes no screenshot files.

Translation sends only the current edited text to Google by default, or to Luna through the selected provider when the user explicitly chooses the Advanced fallback. Requests support cancellation. The picker supports English, Ukrainian, German, Spanish, French, Italian, Polish, Portuguese, Japanese, Korean, Simplified Chinese, and Arabic. The backend validates the selected language against this list. Google requests are limited to 5,000 characters; Advanced requests retain the 100,000 UTF-8-byte limit. While a translation is pending, the text remains visible and temporarily read-only. Failed or empty translations leave it intact and allow retrying, editing, or copying.

The request has a two-minute timeout, a bounded response size, and cancellation when its window is closed or the feature is disabled. Ordered request IDs prevent late requests, cancellation messages, or responses from overriding a newer mode or capture. Local OCR runs on a blocking worker with reusable CPU sessions; cancellation discards its result and skips remaining lines, though a model call already in progress may finish. Clipboard errors preserve the edited text and keep the window open. Native screenshots of protected content may be blank. HDR colors and exclusive fullscreen applications need verification on a Windows desktop.

API contract sources: [Luna model](https://developers.openai.com/api/docs/models/gpt-5.6-luna), [image input](https://developers.openai.com/api/docs/guides/images-vision).

The shared API key uses Live Translate’s Save/Remove flow, including validation before storage. Save displays “Checking key…” while a small Luna Responses request (16 output tokens maximum, no reasoning, `store: false`, no screen content) checks authentication and model access. Only a completed response allows replacing the stored key; invalid keys, service errors, and timeouts preserve it. Saved keys are represented by a fixed mask; the stored secret is never sent back to the webview. Typing replaces the mask with the new password input. Removing the shared key disables API-key access while keeping Basic OCR and Codex sign-in independent.

### Google translation prototype

Translate now defaults to Google’s unofficial web endpoint, including when no Advanced provider is available. The language picker states that text is sent to Google. Requests use POST form bodies without credentials, a reused HTTP client, a 5-second connection timeout, a 12-second total timeout, and a 5,000-character input limit. Unexpected, empty, partial, or oversized responses fail without replacing the draft. No automatic retries or paid fallback occur. **Try again** retries the same provider; **Use Advanced** explicitly sends the current edited text to the configured Codex/API provider. Closing the overlay or changing extraction mode cancels the request and rejects stale results.

Offline transport/parser tests run with `cargo test google_translate`. The opt-in `cargo test live_google_translates_synthetic_text -- --ignored --nocapture` makes two real requests containing only synthetic English/Ukrainian text.
